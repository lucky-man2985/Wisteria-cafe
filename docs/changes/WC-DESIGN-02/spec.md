# Спецификация WC-DESIGN-02

Основание: intent.md. Дата: 15 октября 2026. Это основной источник требований
данного этапа. Состояние — plan.md; фактические проверки — evidence.md.

## Источники и границы

Текущий рабочий прототип находится в
`/workspace/artifacts/wisteria-design-review/`:
`home.html`, `menu.html`, `desserts.html`, `product.html`, `navigation.html`, `accents.html`,
`review.css`, `refinements.css`, `review.js`, `review-data.json` и `assets/`.
Этот путь относится к текущей облачной среде. Передача размещена в отдельной
GitHub-ветке design/wisteria-accents-2026-10-15, каталог design-review/.
Ссылки на просмотр и draft PR записаны в plan.md. Это материалы ревью, не адрес сайта.

Используются исходные `wisteria-brand-logo.jpg`, `wisteria-botanical.jpg`,
фотографии блюд и четыре локальных файла Noto. Логотип не перерисовывается,
оригиналы изображений не редактируются. `review-data.json` содержит 431 позицию
из `dist/menu.json`; перенос данных не означает отображение всего каталога
или наличие серверной БД.

## Как работает прототип

Главная → «Смотреть меню» → каталог или категория «Десерты» → фотография,
название либо «Выбрать» → страница блюда / быстрый просмотр → выбор показанного
варианта и количества → возврат к меню.

Альтернативный вход: шапка → раскрытая навигация → каталог или категория.
На телефоне категории представлены горизонтальной лентой; поиск ограничен
представленными в макете карточками. Пустой поиск получает отдельное состояние.
Число 431 относится к исходному меню, а не к числу показанных карточек.

Конечный результат сценария этого этапа — оценка представления блюда и выбора.
Отправка заказа и оплата в схему не включены. Корзина сообщает, что её полноценное
оформление будет подготовлено после выбора дизайна. Переключатели прототипа
не заменяют проверку бизнес-логики и пересчёта стоимости действующего сайта.

## Требования

| ID | Наблюдаемое требование |
| --- | --- |
| D02-01 | Пять отдельных состояний: главная, каталог, категория десертов, блюдо и раскрытая навигация. Файлы открываются как единый локальный прототип. |
| D02-02 | Молочная основа, белые карточки, тёмный текст, сливовые действия и ограниченные лиловые детали. Фото еды сохраняют главный визуальный приоритет. |
| D02-03 | Исходный логотип сохраняет пропорции и цвета. Акварель располагается у внешнего края композиции, не мешает тексту, ценам и действиям; её белое поле согласовано с фоном через CSS. |
| D02-04 | Карточка показывает фото, категорию/вес, название, описание, сведения об аллергенах и замечания источника, цену и действие. Небольшой лиловый разделитель объединяет карточки без повторяющегося цветочного декора. |
| D02-05 | Избранное имеет различимые состояния. Активная категория обозначена подложкой и формой/маркером. На телефоне прокрутка категорий не создаёт горизонтальной прокрутки всей страницы. |
| D02-06 | Длинное техническое название свекольного салата сокращается только в отображении; исходная запись меню и варианты не переписываются. Базовая цена блюда показана перед настройками, итоговый ценовой блок расположен рядом с основным действием. |
| D02-07 | Локальные Noto Serif и Noto Sans используются без внешней загрузки шрифтов. В карточках desktop: название 17 px, описание 14 px, метаданные 12 px; мобильная версия сохраняет читаемую иерархию. |
| D02-08 | home/menu/desserts/product/navigation/accents проверяются на 360, 390, 768 и 1440 px: ширина документа не превышает viewport, изображения загружены, ошибок JavaScript в зафиксированном прогоне нет. navigation проверяется в открытом состоянии. |
| D02-09 | Пакет review отделён от dist и опубликованной версии. Передача готовится через отдельную ветку от main и draft PR; источник GitHub Pages не переключается. До согласования дизайн не публикуется. |

## Приёмка и ограничения

D02-01, D02-02 и D02-04 проверяются просмотром HTML и снимков desktop/mobile.
D02-03 — также сравнением SHA-256 ассетов с текущими исходниками.
D02-06 — сопоставлением отображаемого имени с неизменённым JSON и просмотром
мобильного блюда. D02-08 — матрицей в `layout-check.json`; автоматическая матрица
сама по себе не доказывает полную доступность, работу каждого переключателя
или отсутствие перекрытий при прокрутке.

Проверки контраста, screen reader, 200% масштаба и Core Web Vitals не считать
выполненными по факту наличия макетов или результатам предыдущего WC-DESIGN-01.
Перед внедрением потребуется отдельная проверка настоящих маршрутов, состояния
корзины, вариантов и сохранения текущей бизнес-логики.

Ответственный за объединение и передачу — основной агент чата. Агент design_review
проверяет визуальные материалы и ведёт только эти четыре документа; он не меняет
HTML/CSS, dist и настройки GitHub. Основной агент проверяет объединённый пакет,
актуализирует evidence.md и plan.md после финального прогона и передачи.
